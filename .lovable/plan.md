## الهدف
إعادة هيكلة معالج التقديم (`/apply`) ليبدأ بعرض القيمة (تأشيرة + متطلبات + سعر) قبل أي بيانات شخصية، ثم بوابة دخول موحّدة (Google + بريد) قبل خطوات الإكمال. كل الطلبات — سواء إلكترونية أو عبر واتساب — تُحفظ في حساب العميل ولوحة `سجلاتي`.

## التدفق الجديد

```
الخطوة 1: اختر التأشيرة          (دون تسجيل)
   • الدولة + نوع التأشيرة + عدد المسافرين + تاريخ السفر المتوقع

الخطوة 2: المتطلبات + السعر       (دون تسجيل)
   • قائمة المستندات المطلوبة (للاطلاع فقط)
   • السعر الإجمالي الواضح + ملاحظات الرسوم الحكومية
   • زر "متابعة" + زر "إلغاء/عودة" بحرية

──────── 🔐 بوابة الدخول ────────
   • متابعة بحساب Google (نقرة واحدة)
   • متابعة بالبريد وكلمة المرور (تسجيل / دخول)
   • العميل الموجود مسبقاً → دخول مباشر

الخطوة 3: اختر طريقة الإكمال      (بعد تسجيل الدخول)
   ┌──────────────────────────┬──────────────────────────┐
   │ 🌐 إكمال إلكتروني        │ 💬 إكمال عبر واتساب      │
   │ → الخطوة 4: رفع المستندات│ → ينشئ طلباً VF-YYYY-XXXX │
   │ → الخطوة 5: الدفع + شروط │   ويفتح واتساب فوراً     │
   │                          │ → الطلب يظهر في "سجلاتي"  │
   └──────────────────────────┴──────────────────────────┘
```

## التغييرات التقنية

### 1) قاعدة البيانات
- **`applications.user_id`**: يعود **NOT NULL** (كل الطلبات الآن مربوطة بحساب). إزالة أعمدة `guest_*` التي أُضيفت مؤخراً (لم تعد ضرورية).
- **`create_whatsapp_order` RPC**: إعادة كتابتها لتستخدم `auth.uid()` بدلاً من بيانات ضيف، وتجلب الاسم/البريد/الجوال من `profiles`.
- **migration** لإلغاء أعمدة `guest_full_name/email/phone/country_code` بعد التأكد من عدم وجود بيانات حقيقية فيها.

### 2) إعدادات Auth
- التأكد من تفعيل **Google OAuth** (مفعّل بالفعل عبر `lovable.auth`).
- التأكد من تفعيل **Email + Password**.
- **تعطيل** أي مزود غير مستخدم (Apple إن كان مفعّلاً).

### 3) معالج التقديم (`/apply`)
- **حذف** `Step1BasicInfo.tsx` (الاسم/البريد/الجوال) — البيانات تأتي من حساب المستخدم تلقائياً.
- **إعادة ترقيم الخطوات**:
  - Step 1 = `Step2VisaDetails` السابقة (تفاصيل التأشيرة)
  - Step 2 = `Step3Requirements` السابقة (المتطلبات + السعر)
  - Step 3 = `PathChoiceCard` (إلكتروني / واتساب) — تظهر فقط بعد تسجيل الدخول
  - Step 4 = `Step4Documents` (رفع المستندات)
  - Step 5 = `Step5Payment` (الدفع + checkbox الشروط)
- **`AuthGate` جديد**: يظهر بعد ضغط "متابعة" في Step 2 إذا كان المستخدم غير مسجّل.
  - يعرض زرين: **Google** و **بريد/كلمة مرور**
  - بعد نجاح الدخول → الانتقال تلقائياً لـ Step 3 مع حفظ مسودة الطلب
- **حذف** `localStorage` لبيانات الضيف (لم تعد ضرورية).

### 4) WizardStepper
تحديث الشريط ليعرض 5 خطوات جديدة بالأسماء الصحيحة بالعربية.

### 5) مسار الواتساب
- يستدعي `create_whatsapp_order` (التي تستخدم `auth.uid()` الآن)
- ينشئ تطبيقاً بحالة `whatsapp_pending` مربوط بـ profile العميل
- يظهر في **`/my-applications`** (سجلات العميل) مع رقم `VF-YYYY-XXXX`
- يفتح واتساب مع رسالة تتضمن رقم الطلب

### 6) لوحة العميل
- التأكد أن `/my-applications` تعرض الطلبات بحالة `whatsapp_pending` مع شارة مميزة "📱 قيد المتابعة عبر الواتساب"
- زر "متابعة الإكمال إلكترونياً" يحوّل المسار من واتساب إلى إلكتروني إن أراد العميل لاحقاً

### 7) لوحة الأدمن
- بطاقة "إثبات الموافقة على الشروط" (موجودة فعلاً) تبقى كما هي
- إزالة أي إشارة لبيانات الضيف من `ApplicationDetail.tsx`

## ما يبقى كما هو
- الموافقة على الشروط والأحكام (checkbox + حفظ IP/UA/version) في خطوة الدفع
- منطق الـ `display_number` (`VF-YYYY-XXXX`)
- إشعارات الأدمن عند طلب واتساب جديد
- منطق الرفع للمستندات وSaudi S3
- التحقق من المدخلات بالإنجليزية + 9 أرقام للجوال

## الفوائد المتوقعة
1. **رفع التحويل**: العميل يرى السعر قبل أن يُطلب منه أي شيء → قرار واعٍ
2. **حذف التكرار**: بيانات شخصية تُدخل **مرة واحدة فقط** (عند التسجيل)
3. **لوحة موحّدة**: كل طلب — حتى عبر الواتساب — يظهر في `سجلاتي`
4. **بساطة قصوى**: لا Twilio، لا SMS، لا WhatsApp Business API — صفر تكاليف خارجية
5. **حل التناقض المنطقي** الذي رصدته بدقة

## مخاطر يجب الانتباه لها
- ⚠️ بعض العملاء قد يتسربون عند بوابة الدخول — لذلك زر Google بنقرة واحدة ضروري في المقدمة
- ⚠️ حذف أعمدة `guest_*` يحتاج التأكد من أن لا طلبات حقيقية تستخدمها (نتحقق قبل migration الحذف)
